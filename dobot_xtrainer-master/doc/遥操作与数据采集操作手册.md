# 遥操作与数据采集操作手册

> 适用程序：`experiments/launch_nodes.py`（robot server）+ `experiments/run_control.py`（采集主程序）
> 设备：2× Dobot Nova 从手 + 2× Dynamixel 主手 + 3× RealSense 相机
> 专有名词、按钮名、变量名保持原文不翻译。

---

## 0. 先理解一件事：程序不会「停下来等你输入」

`run_control.py` 初始化完、打印出 `Ok, let's start` 后，会进入一个**高速主循环持续运行**。
但在你**按下主手上的按钮**之前，从手不会跟随、也不会录制——所以体感上像「停在那里等你」。
它等待的是**按键事件**（Button A / Button B），不是某个 `input()` 阻塞。

---

## 1. 系统状态总览（灯语）

| 灯色 | 含义 |
|------|------|
| 灭 | 初始 / 未开始跟随 |
| 黄 | servo 已开启，遥操作中，**未录制** |
| 绿 | **正在录制数据** |
| 红 | 出错（多为主从手偏差过大 / 动作跳变过大） |

## 2. 按键速查表（主手按钮）

| 操作 | 按钮 | 效果 |
|------|------|------|
| 短按（<0.5s） | Button A（黄色） | 主手 **锁定 ⇄ 解锁**（力矩开/关，用于手动摆姿） |
| 长按（>1s） | Button A（黄色） | 从手 **跟随 servo 开 / 关** |
| 按一下 | Button B | **录制 开 / 关**（必须已开 servo 才生效） |

> 左右手的 Button A 独立控制各自一侧，可单臂操作。

---

## 3. 完整操作流程（分阶段）

### 阶段 0：开机前物理准备
- 确认 2 台 Nova 从手、2 只 Dynamixel 主手、3 台 RealSense 相机均通电、连线正常。
- 确认从手处于**安全、可自由运动**的位置（下一步会自动移动）。
- 确认从手网络连通、TCP/IP 模式已开启（左 `192.168.5.1` / 右 `192.168.5.2`）。

### 阶段 1：启动 robot server
```bash
python experiments/launch_nodes.py
```
- 本步会**使能两台从手**、初始化夹爪（夹爪会开合一次），随后 ZMQ server 阻塞等待 client。
- ⚠️ 本步**不会**让从手移动到初始姿态，仅上电使能；移动在阶段 2 完成。
- **此终端保持开启，不要关闭。**

### 阶段 2：启动采集主程序（另开一个终端）
```bash
python experiments/run_control.py
```
程序自动依次执行：
1. 相机初始化（约 2 秒）
2. 主手串口连接
3. 连接从手 client
4. 固件版本检查
5. **`robot_pose_init`：从手自动缓慢运动到初始姿态**（分两段）
6. 打印 `-------------------------Ok, let's start------------------------`
7. 进入主循环，等待按键

- 🔴 **安全点**：第 5 步从手会**自行运动**，人手与身体请离开机械臂工作范围。
- 看到 `Ok, let's start` 即代表就绪。

### 阶段 3：对齐主手与从手（人工，关键）
从手此时停在初始姿态，需要把主手姿态与之对齐：
1. **双手分别握稳左右主手**（务必先握稳，解锁瞬间力矩归零会因重力下坠）。
2. **短按黄色按钮（Button A，<0.5s）解锁主手** → 力矩关闭，可自由拖动。
3. **拖动主手**，使其姿态与对应从手（初始姿态）尽量一致。
4. 对齐后继续握住即可，无需重新锁定（下一步长按会自动接管力矩）。

### 阶段 4：开启从手跟随（servo）
- **长按黄色按钮（Button A，>1s）** 开启该侧从手跟随。
- 触发瞬间程序执行 `dynamic_approach`：**从手缓慢移动到主手当前姿态**，并做 `pose_check` 偏差检查。
  - 偏差过大 → **红灯**报错：说明阶段 3 未对齐好，重新摆姿后再长按。
  - 成功 → **黄灯亮**，进入遥操作待录制状态。
- 左右手可分别开启（单臂任务只长按一侧即可）。

### 阶段 5：遥操作 + 录制数据
- 移动主手，**从手实时跟随**（即遥操作）。
- **按 Button B 开始录制** → **绿灯亮**，开始把三路图像 + observation/action 落盘；每次「开始录制」生成一个新的时间戳文件夹（= 一条轨迹）。
- 完成一条轨迹后，**再按 Button B 停止录制** → 回到**黄灯**。
- 重复「Button B 开 → 操作 → Button B 关」采集多条轨迹。

### 阶段 6：结束
- **长按 Button A 关闭该侧 servo**（从手停止跟随）。
- **Ctrl+C 退出**采集程序（已做 daemon + finally 清理，一次即可干净退出并释放相机/ZMQ）。
- 关闭 server 终端；从手按常规流程断电/复位。

## 4. 数据落盘位置

```
<save_data_path>/<project_name>/collect_data/{时间戳}/
    ├── topImg/       顶部相机 jpg（0.jpg, 1.jpg, ...）
    ├── leftImg/      左相机 jpg
    ├── rightImg/     右相机 jpg
    └── observation/  每帧的 obs+action pkl
```
- 默认 `project_name = "plug_and_unplug_task"`，`save_data_path` 见 `run_control.py` 的 `Args`（指向 `~/datasets/`）。
- 每个 `{时间戳}` 文件夹 = 一条轨迹，对应一次「Button B 开 → 关」。

---

## 5. 关键顺序（一句话记忆）

> **起 server → 起采集(从手自动归位) → 握主手 → 短按解锁 → 摆姿对齐 → 长按开跟随(黄灯) → Button B 录制(绿灯) → 再按停 → 长按关跟随 → Ctrl+C**

---

## 6. 常见坑与安全提醒

- **必须先长按开 servo（黄灯），Button B 才录得上**；未开 servo 时按 B 不会保存数据。
- **解锁主手前务必先握稳**，否则力矩归零瞬间机械臂下坠。
- **红灯 = 对齐失败**（主从手偏差过大或动作跳变），松开重新摆姿再长按。
- 阶段 2 的 `robot_pose_init` 会让**从手自动运动**，启动后人先离开工作范围。
- server 终端与采集终端是**两个独立进程**，采集期间 server 终端不要关。
- 若采集程序启动后长时间卡在 "Waiting to connect the robot..."，多为 server 未起或网络/TCP-IP 模式问题（注意：当前 ZMQ client 无接收超时，会一直等待）。
